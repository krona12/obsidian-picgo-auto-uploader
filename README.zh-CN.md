# PicGo 自动上传

[English](README.md)

PicGo Auto Uploader 是一个安全优先的 Obsidian 插件，用于把云同步到电脑的本地图片附件转换成 PicGo 图床链接。它仅支持 Windows 桌面版，需要 Obsidian 1.7.2 或更高版本，并且仅在 Obsidian 打开时运行。

插件会扫描仓库普通目录中的受支持图片，等待文件停止变化，只上传确实被引用的图片，一次处理一张，改写全部受支持的 Markdown 图片引用，重新验证结果，最后才永久删除本地源文件。隐藏目录和仓库回收站会被排除；遇到任何不确定情况都会保留本地文件。

## 使用条件

- Windows 桌面系统与 Obsidian 1.7.2+。
- 已启用 HTTP Server 的 PicGo。默认地址为 `http://127.0.0.1:36677`。
- PicGo 中已有可用的图床提供商配置。
- 必须准备备份或文件历史。成功转换后会永久删除本地源文件，请先在小文件夹中试用，再处理重要 Vault。

**测试连接**只调用 PicGo 的 `POST /heartbeat` 接口。实际上传通过 `POST /upload` 完成，每次请求只发送一张图片；心跳成功不代表之后的上传一定成功。

## 工作流程

1. 启动扫描、文件创建/修改事件以及每五分钟的校准扫描会在仓库普通目录中查找候选图片。默认扫描整个仓库，也可以关闭后限制为已配置的附件文件夹。
2. 文件必须符合扩展名和大小限制，并在设定的稳定观察期间保持不变。
3. Obsidian 元数据必须把至少一个受支持的图片引用精确解析到这个源文件。孤立图片既不会上传，也不会删除。
4. 插件先创建保留原文件名的不可变临时快照，再把快照的 Windows 绝对路径发送给 PicGo。只有确认快照已经删除，才允许永久删除 Vault 源图；若 Windows 暂时占用快照，插件会持久保存不含绝对路径的清理标识和已确认 URL，同时保留源图。后续校准只重试清理；即使上传状态为“不确定”，也不会借清理之机重新上传、改写或删除源图。若上次运行崩溃，启动时只清理本插件遗留的快照，不会触碰其他仍在运行进程的快照。响应必须只包含一个经过验证的 `http:` 或 `https:` URL。
5. 在修改笔记前先持久保存确认后的 URL 和快照 SHA-256。重新启动后，只有当前源文件内容哈希完全相同，才会复用已保存的 URL。
6. 改写所有受支持引用，并使用最新的笔记内容和元数据再次验证。
7. 只有全部删除门槛都通过后，才调用 Obsidian 的永久删除接口；源文件不会留在 Vault `.trash` 或 Windows 回收站。

上传任务串行执行。请求发出后的超时或断开会标记为“不确定”，不会自动重试，因为 PicGo 可能已经上传成功。明确重试前请先检查 PicGo 和图床提供商；重试可能生成重复的远程图片。

## 支持的内容

默认启用全仓库扫描，所以 `root-image.png` 这类位于仓库根目录的图片也会先被发现，再检查是否存在 Markdown 引用。`.obsidian`、`.trash` 等带点号的隐藏路径始终排除。关闭 **扫描整个仓库** 后，插件只检查配置的附件文件夹；默认回退文件夹为 `attachments`。支持的图片扩展名严格为 `png`、`jpg`、`jpeg`、`gif`、`webp`、`bmp`、`svg` 和 `avif`。

支持的图片引用包括：

```markdown
![[attachments/image.png]]
![[image.png|替代文字]]
![[image.png|300]]
![替代文字](attachments/image.png)
![替代文字](<attachments/image with spaces.png> "标题")
```

插件会在引用所在笔记的上下文中精确解析目标，而不是只按文件名猜测。转换为外部图片引用时，会保留 Markdown 替代文字、标题以及 Obsidian 的显示文字/尺寸。

在 Markdown 文件内，本地 HTML `<img>`、引用式/块级链接、格式错误的引用以及其他原始依赖不会被改写，但只有在可能指向当前目标图片时才阻止删除。已确认是 HTTP(S) 外链的 HTML 图片及与目标无关的损坏图片语法，不再阻塞所有附件。Markdown 之外，仅对 `.canvas`、`.base` 和 `.html` 文件进行保守扫描；只有匹配当前目标路径或文件名时才阻止删除。

0.1.2 不会解析或扫描其他格式，包括 Excalidraw 和未知插件数据。只保存在未知插件数据中的引用无法检测，也不受保护；删除检查不会因为这类引用而阻止删除。不要为仅被这些格式依赖的附件启用自动处理；请保留备份并先用小文件夹测试。可能涉及当前目标的 Markdown 元数据缺失或过期、受保护文件不可读、目标范围重叠、并发编辑也会保留源文件。

## 删除安全门槛

只有同时满足以下条件，源文件才会被永久删除：

- PicGo 返回且只返回一个经过验证的远程 URL。
- 至少有一个引用确实改写成功。
- 最新引用验证没有发现任何本地或歧义依赖。
- 源文件的大小、修改时间和 SHA-256 与 PicGo 实际上传的快照完全一致。
- 不存在仍待清理的私有上传临时快照。
- 插件生命周期仍处于活动状态。
- 当前文件仍是正在处理的精确源文件身份。

上传、改写、验证、指纹、生命周期或删除前检查发生任何错误时，都会保留本地附件并记录脱敏状态；能确定时还会记录第一篇阻塞笔记的仓库相对路径。孤立附件也留在本地。插件会先持久记录 `deleting` 删除意图；重启恢复能区分“已经删除”和“原文件仍在”，并且绝不会把旧意图用于同路径的新内容。唯一的删除操作是 `Vault.delete(file, true)`，且只能通过完整安全门槛到达；无法从 Vault `.trash` 或 Windows 回收站恢复。

## 隐私与网络访问

插件会读取符合条件的 Vault 图片、Markdown 笔记和 Obsidian 元数据。它只向已配置的 PicGo 端点发送短期私有快照的 Windows 绝对路径以及可选的 Bearer 密钥。随后由 PicGo 读取快照，并把图片字节发送给用户选择的图床提供商。

0.1.2 不收集遥测，也不会探测返回的 URL，不会连接分析服务。日志与导出的诊断信息会脱敏密钥和绝对路径，不包含图片字节或 PicGo 任意响应正文。

为了兼容 Obsidian 1.7.2，0.1.2 不依赖较新的 SecretStorage API。可选密钥会以明文保存在本插件本地的 `data.json`；同步这个文件可能暴露密钥。如果无法接受，请从同步中排除 `.obsidian/plugins/picgo-auto-uploader/data.json`，或者不要保存密钥。

明文 HTTP 只有保持在本机时才能避免被网络旁观者读取。非本机的 HTTP 端点会在网络中暴露路径和凭据，因此设置页要求显式确认风险。建议使用回环地址或 HTTPS。

## 设置与状态中心

在 **设置 → 第三方插件 → PicGo Auto Uploader** 中配置自动处理、全仓库或指定文件夹扫描、PicGo 地址/密钥、扩展名、大小限制、时间参数和历史保留。无效设置不会生效；**测试连接**只调用 `POST /heartbeat`。

可通过功能区图标、状态栏或命令面板打开非持久化状态中心。它显示 PicGo 可用性、自动处理状态、队列/历史、上次扫描、上次成功转换、脱敏错误和安全操作。可以立即扫描、重试安全失败项、确认后重试不确定项、取消待处理任务、清除已完成历史以及导出脱敏诊断。

三个命令的准确名称为：

- `Open PicGo Auto Uploader status`
- `Scan referenced images now`
- `Retry failed uploads`

## 恢复方法

1. 排查时先停用自动处理。
2. 必要时从备份、同步历史或文件历史恢复已永久删除的附件。
3. 从同一备份或历史来源恢复、回退 Markdown。
4. 查看状态中心并导出经过脱敏的诊断信息。
5. 对“不确定”上传，重试前先检查 PicGo 和图床提供商；远程文件可能已存在，显式重试可能产生重复的远程图片。

插件不会删除远程图片。请保持 Vault 定期备份，并先在小文件夹中试用。

## 手动安装

1. 打开 [Releases](https://github.com/krona12/obsidian-picgo-auto-uploader/releases)，从同一个版本下载 `main.js`、`manifest.json` 和 `styles.css`。
2. 创建 `<vault>/.obsidian/plugins/picgo-auto-uploader/`。
3. 将三个文件直接复制到该目录。
4. 重新加载 Obsidian，然后在第三方插件中启用 **PicGo Auto Uploader**。

不要把 GitHub 的源码 ZIP 当作插件包；它不包含经过审计的构建文件。

## 故障排查

### PicGo 离线

启动 PicGo 并开启 HTTP Server，核对端口后使用**测试连接**。默认地址是 `http://127.0.0.1:36677`。防火墙或不同端口也可能阻止访问。

### 图片被跳过

确认已启用全仓库扫描（或图片位于配置的回退文件夹中）、扩展名已启用、文件没有超过大小限制，并存在受支持的 Markdown 图片引用。孤立与歧义引用会被有意保留。

### 任务显示“不确定”

连接在上传请求发出后中断。选择显式重试前先检查 PicGo/图床历史；在没有幂等协议的情况下，不存在安全的自动重试。

### 已返回 URL 但文件仍然存在

当改写或最终验证无法证明安全时，这是预期结果。查看脱敏错误，修复不受支持或过期的引用后重试。安全恢复改写时会复用已保存 URL，避免重新上传。

## 开发

需要 Node.js 22.12 或更高版本。

```powershell
npm ci
npm test
npm run check
npm run package
```

`npm run check` 会执行格式检查、代码检查、类型检查、覆盖率测试、构建和发布审计。`npm run package` 生成 `release/`，其中严格只有 `main.js`、`manifest.json` 和 `styles.css`。

开发和发布规则见 [CONTRIBUTING.md](CONTRIBUTING.md)，私密漏洞报告方式见 [SECURITY.md](SECURITY.md)，版本记录见 [CHANGELOG.md](CHANGELOG.md)。
